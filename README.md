# TRUST://BREAK

**Everyone remembers something. Nobody remembers everything.**

Built for AGENTHON 2026 (12-hour hackathon, Sept 27 2026).

## Play

You are the emergency commander of station ORION. Five AI crew members are online. One caused the reactor sabotage. Interrogate them, cross-check their statements against the evidence panel, and file a formal accusation before the 8-minute timer runs out.

- Click a crew member to open questioning
- Ask any of 6 questions — answers depend on that agent's actual state, not a fixed script
- Check **EVIDENCE** for clues that can contradict what an agent just told you
- **SYSTEM.LOG** shows live reasoning (trust/suspicion changes) — it never reveals who the culprit is
- **FORMAL ACCUSATION** ends the game — choose correctly before integrity (time) runs out

## What makes it "AI"

This isn't one chatbot — it's five independent agents, each with their own:

`personality · behavior type · trust toward player · suspicion level · memory of questions asked · true knowledge vs. what they choose to say · a hidden hand in a possible cover story`

Every game randomly assigns **one agent as the saboteur** and gives the other four **four distinct behavior types** drawn from: Honest, Helpful, Defensive, Manipulative, Confused. That mix is what creates real deduction:

- An **Honest/Helpful** witness may have genuinely seen the saboteur near the reactor — a real lead.
- A **Manipulative** agent (who may or may not be the saboteur) will falsely finger an innocent crewmate — a deliberate red herring you have to verify against that crewmate's own consistent alibi.
- The saboteur always denies reactor access and gives a false alibi — but **Evidence EV-01** (a badge scan) contradicts it if you check.
- Asking the same question twice costs you trust ("I already told you that") — investigation has a cost, so question choices matter.
- Suspicion levels on the crew panel move in real time based on *testimony*, not ground truth — so a red herring can genuinely raise an innocent agent's suspicion bar. Don't accuse on suspicion alone; cross-reference with evidence.

## Technical details

- **No LLM, no API key, no backend.** All agent dialogue is generated by `getResponse(agent, questionId)` in `game.js`, a deterministic function that reads each agent's state (behavior type, claimed vs. actual location, who they claim to have seen, memory of past questions) and returns text plus trust/suspicion side effects.
- **Replayable by construction:** culprit, behavior assignments, alibi lies, and the red-herring evidence target are all randomized per game. 500 randomized generation trials were run to confirm every scenario always produces exactly one traitor, four distinct non-traitor behavior types, and no runtime errors across a full question-and-accusation playthrough.
- **Upgrade path:** `getResponse()` is isolated from rendering and state management specifically so it can later be swapped for a real LLM call (e.g. send the agent's state object as context to an API and use the returned text instead) without touching the trust/suspicion/memory/evidence systems.
